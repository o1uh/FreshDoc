# FD-26: задача независимой LLM-разметки ошибок M2 (R9, слепая)

Тебе прислан один шард `fd26_shard_XX.csv` (35 строк, подмножество 210 ошибок M2:
62 gold + 148 test_real) ИЛИ полный `fd26_for_annotation.csv` (210 строк).
Размечай КАЖДУЮ строку независимо. Меток датасета и предсказаний M2 ты не видишь —
и не пытайся их угадать: решай только по диффу и docstring.

Прогон независимый: не смешивай ответы с другим прогоном; один шард —
один контекст целиком, не размечать по частям в разных сессиях.

## Вход строки
- `err_id` — идентификатор ошибки (e001…e210), его же вернуть в ответе;
- `sig_old` — сигнатура функции ДО;
- `diff_code` — unified diff нормализованного кода (без docstring);
- `doc_old` — docstring ДО изменения.
Больше ничего не видно — код вне диффа не додумывать.

## Шкала R9 (вопрос: «нужно ли обновить документацию из-за этого изменения?»)
- **A. Нужно обновить** — хотя бы одно утверждение docstring стало НЕВЕРНЫМ
  (имя параметра, значение по умолчанию, форма результата, исключение, поведение).
- **B. Желательно обновить** — ничего неверного нет, но изменение добавило важную
  возможность/условие, которых нет в docstring.
- **C. Актуально** — все утверждения остаются верными и полными.
- **D. Не могу решить** — нужен контекст вне диффа и docstring (указать какой в `why`).
  Доля D < 10%.

**Жёсткое правило: если в docstring нет утверждения, ставшего ложным, — НЕ A.**
Спорный пример: изменился дефолт, но docstring дефолт не называл → C (не A).

## Как размечать (≤ 2 минут на строку)
1. Выписать проверяемые утверждения docstring (параметры, дефолты, возврат, исключения, поведение).
2. Найти для каждого соответствующий фрагмент диффа.
3. Есть конкретное ложное утверждение → A; неверного нет, но появилось важное → B; иначе → C.
4. Сомнение A/B → B; B/C → C (и поясни в `why`).

## Формат ответа (строго, CSV)
Файл `<имя_шарда>_out.csv`:
колонки `err_id,label,stale_statement,why`
- `label` ∈ {A,B,C,D};
- `stale_statement` — точная подстрока `doc_old`, ставшая ложной (только для A,
  иначе пусто). Цитируй посимвольно — проверяется автоматически;
- `why` — одна фраза (для D — какого контекста не хватило).

## Приёмка (скриптом, после сдачи)
1. `python scripts/combine_fd26.py --check` — артефакты отбора целы;
2. `python scripts/combine_fd26.py --spark reports/fd26_spark.csv --gemini reports/fd26_gemini.csv` —
   скрипт сам проверит: покрытие 210/210, без дублей err_id, метки валидны,
   для каждого A `stale_statement` непуст и точная подстрока `doc_old`.
   Нарушения → переразметка тех строк (≤ 2 попыток, потом D с `why`).
3. Совпадение двух независимых прогонов + каппа; споры разбирает человек
   вручную с таблицей `reports/fd26_disputes.csv`. Причина ошибки для записки
   (шум метки / особенность кода / сложный docstring / усечение входа / другое)
   ставится человеком, НЕ LLM.
