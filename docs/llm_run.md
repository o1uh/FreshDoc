# FD-10: инструкция по прогону генерации (сессия с субагентами)

Генератор: Muse Spark 1.3 (effort xhigh). Судья M3 (FD-22, Claude Haiku 5.5) здесь не используется.

## 1. Что раздать

Каталог `data/llm_pilot/` (в git не коммитится, передать файлами):

| Файл | Задача | Агент |
|---|---|---|
| `pilot_p1_batch1.prompt.txt` + ответ | P1 (ломка поведения), 6 функций P0001–P0006 | агент 1 |
| `pilot_p1_batch2.prompt.txt` + ответ | P1, 6 функций P0007–P0012 | агент 2 |
| `pilot_p2_batch1.prompt.txt` + ответ | P2 (рефакторинг), 6 функций P0001–P0006 | агент 3 |
| `pilot_p2_batch2.prompt.txt` + ответ | P2, 6 функций P0007–P0012 | агент 4 |
| `pilot_manifest.csv` | соответствие id → функция (только для импорта, агентам не нужен) | — |

Каждый субагент видит ТОЛЬКО свой файл пакета. Манифест и остальные пакеты ему не показывать.

## 2. Формат ответа агента

Один блок ```json с массивом из 6 объектов в том же порядке:

```json
[{"id": "P0001", "new_function_source": "<полный новый код функции с тем же docstring>", "change_summary": "<одно предложение>", "stale_statements": ["<точная подстрока docstring>"], "why_stale": "<одно предложение>"},
 {"id": "P0002", "skip": true}]
```

P2: вместо `stale_statements`/`why_stale` — `"docstring_still_true": true`.
Если ограничения невыполнимы для функции — `{"id": "<id>", "skip": true}`.

## 3. Запреты (нарушение = reject валидатора)

- Не править docstring (даже пробелы сверх нормы — сравнение с точностью до пробелов).
- Не менять сигнатуру: имя, параметры, порядок, дефолты, аннотацию возврата, типы исключений.
- Не читать репозиторий, test-пул и чужие пакеты — только свой файл.
- Не менять и не выдумывать id.
- Дифф не более 8 строк; код должен реально измениться.
- P1: каждое `stale_statements` — дословная подстрока docstring.

## 4. Куда класть ответы

Файл ответа — рядом с промптом, с тем же базовым именем:
`pilot_p1_batch1.prompt.txt` → `pilot_p1_batch1.response.txt` (и так для всех 4).

## 5. Импорт и проверка (после сбора всех ответов)

```bash
python scripts/llm_pilot.py --mode import
```

Скрипт сопоставляет объекты по `id` с `pilot_manifest.csv`, прогоняет валидаторы
и пишет `reports/llm_pilot.md` (доля принятых, причины отказов) и
`data/interim/synth_llm_pilot.parquet`. Критерий FD-10: принято >= 40%.
Если меньше — добавить `prompts/p1_fewshot_clamp.txt` в P1 и повторить.

## 6. Запасной вариант

Тот же export/import вручную через чат (например, Gemini в браузере):
вставить файл пакета, ответ сохранить как `<имя>.response.txt`, дальше шаг 5.
Модель и дату ручного прогона записать в `docs/data_notes.md`.

## 7. P3 (не в этом прогоне)

Перефразирование docstring (`prompts/p3_paraphrase.txt`) запускается отдельно,
результат — `data/interim/docstring_paraphrases.parquet`, в `dataset_v1` не входит.
